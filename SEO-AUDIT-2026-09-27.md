# SEO Audit: https://invoicescheduler.com/

**Audit date:** 27 Sep 2026 · **Method:** live HTTP fetches (curl) of the production site, HTML parsing of the served page, header/redirect/status testing, robots.txt + sitemap review, SERP checks via web search, competitor page review (Zoho, Bloom). PageSpeed Insights API was over quota during the audit, so performance findings are from resource analysis (lab/CrUX field data **could not be verified**).

**Evidence labels:** **[Confirmed]** = directly observed in live responses · **[Likely]** = strong inference from evidence · **[Unverified]** = could not be tested from outside (needs GSC / real browser / PSI).

> ⚠️ **This file describes live security exposures. Do not upload it to the web root.** Move it out of `htdocs` or add it to your deploy excludes.

## 0. Stop-ship: security exposures found during the audit

These aren't SEO issues in the usual sense, but they're the most urgent findings. Publicly indexable files are also an SEO problem, because Google can and does index `.sql` and backup files.

| URL | Live status | What it is |
|---|---|---|
| `/invoice_gendb.sql` | **200, `text/x-sql`**, last-modified 8 Sep 2026 | Full database dump (2.9 MB locally). **[Confirmed]** publicly downloadable. I did not download it. |
| `/test-db` (`/test-db.php`) | 200, body: `Connected to database successfully!` | DB connection test script **[Confirmed]** |
| `/index-bkp9sept` | 200, `index, follow`, 226 KB | Backup copy of the homepage **[Confirmed]** (also duplicate content) |
| `/composer.json`, `/composer.lock` | 200 | Dependency manifest (reveals library versions) **[Confirmed]** |
| Response header `x-powered-by: PHP/8.3.33` | on every page | Version disclosure **[Confirmed]** |

**Fix now:**
1. Delete `invoice_gendb.sql`, `index-bkp9sept.php`, `test-db.php` from the server. Keep SQL dumps outside the web root.
2. **Assume the dump has been accessed.** Rotate the DB password and any API/SMTP keys, invalidate sessions, and force password resets if it contains user credentials. Review Hostinger access logs for requests to the file. If it contains customer personal data, check your breach-notification obligations (e.g. GDPR / India DPDP).
3. Block sensitive files in `.htaccess` as defense in depth:
```apache
<FilesMatch "\.(sql|bak|log|env|ini|lock)$|^composer\.(json|lock)$|^(test-db|.*-bkp.*)\.php$">
  Require all denied
</FilesMatch>
Header unset X-Powered-By
```
4. After removal, use **GSC → Removals** for any of these URLs that appear in `site:invoicescheduler.com`.

## 2. Title Tag Audit

**Current title:** `Free Invoice Generator & Scheduler Online — Create, Send & Schedule Invoices | InvoiceScheduler`

- 95 characters, ≈ 620–650 px. **Will truncate** (Google shows ~580–600 px). "…Schedule Invoices | InvoiceScheduler" is likely cut.
- Primary keyword first ✔. Brand at end ✔.
- "Scheduler… Schedule" repeated, and "Create, Send & Schedule" is filler that is also used in the Guides title (overlap).
- CTR: "Free" is good, but the differentiator (recurring/automatic) isn't clear.

**Recommended title:** `Free Invoice Generator & Recurring Invoice Scheduler | InvoiceScheduler` (71 chars, ~560 px)
**Reason:** Keeps the head term first and puts the real differentiator second. The brand term appears naturally, and it fits without truncation on most devices.

**Alternatives:**
1. `Free Invoice Generator with Recurring Scheduling | InvoiceScheduler` (67)
2. `Free Invoice Generator: PDF Invoices + Automatic Recurring Billing` (65, drop brand if you'd rather Google appends the site name)
3. `Free Recurring Invoice Generator — Create, Schedule & Send PDFs` (63, if you decide to target the recurring niche over the head term, which is the more winnable option for a new domain)

## 3. Meta Description Audit

**Current (189 chars):** "Create professional invoices for free with InvoiceScheduler. Schedule recurring invoices, add your logo, send via email, and download as PDF. No signup required — start invoicing instantly."

- **Truncates** at ~155–160 chars, cutting "No signup required", the strongest CTR hook.

## 4. URL Audit

| Check | Finding |
|---|---|
| Homepage URL | `https://invoicescheduler.com/`: clean, lowercase, HTTPS ✔ |
| HTTP → HTTPS | `http://invoicescheduler.com/` → 301 → `https://invoicescheduler.com/` ✔ **[Confirmed]** |
| **www host** | `https://www.invoicescheduler.com/` returns **200** with identical HTML (no redirect). `http://www` → `https://www` (not to apex). **[Confirmed]** Duplicate host, mitigated only by the canonical tag. |
| **/index duplicate** | `/index.php` → 301 → `/index`, which returns **200** with identical HTML. **[Confirmed]** The site logo links to `/index.php`, creating a crawl path to the duplicate. |
| Parameters | `/?utm_source=x` → 200, canonical points to `/` ✔ |
| 404 handling | `/nonexistent-page-xyz` → 404 ✔. But **missing files under `/assets/` return 500** (e.g. `/assets/nothing.png`) **[Confirmed]**. That's caused by the rewrite rule appending `.php` in a loop. |
| Trailing slash / clean URLs | `.htaccess` 301s `*.php` → extensionless ✔, but internal links, canonicals and sitemap still use `.php` (see §9, §13). |

**Fix (.htaccess, top of file):**
```apache
RewriteEngine On
# Force apex + HTTPS in one hop
RewriteCond %{HTTP_HOST} ^www\.(.+)$ [NC]
RewriteRule ^ https://%1%{REQUEST_URI} [R=301,L]
# /index and /index.php -> /
RewriteCond %{THE_REQUEST} \s/+index(\.php)?[\s?] [NC]
RewriteRule ^ / [R=301,L]
# (existing .php -> clean rule here)
# Only map to .php if that file exists (stops the 500 loop)
RewriteCond %{REQUEST_FILENAME} !-d
RewriteCond %{REQUEST_FILENAME} !-f
RewriteCond %{DOCUMENT_ROOT}/$1.php -f
RewriteRule ^(.+?)/?$ $1.php [L]
```
No homepage URL change needed.

## 6. Content Quality Audit

**Current state [Confirmed]:** ~590 visible words (incl. form labels). About 350 are real marketing copy. The copy is clear but generic ("invoice smarter", "get paid faster", "seamless, convenient, and secure"). It reads as template/AI SaaS copy with no specifics, numbers, screenshots or examples.

**Strengths:** the tool is immediately usable (best possible intent match). The 3-step section is useful. Local-storage behavior is disclosed honestly in the History panel.

**Weaknesses:**
- **Thin on the differentiator.** Scheduling gets one sentence. Users need to know: does it email the client automatically? From what address? What frequencies (the form offers 8: Weekly, Bi-Weekly, Monthly, Bi-Monthly, Quarterly, Tri-Yearly, Half-Yearly, Yearly)? Start/end dates? Can I review before it sends?
- **Contradictory claims:** "No signup required" vs. login-gated sending/scheduling.
- **Unsupported trust claim:** "Trusted by Freelancers, Small Businesses & Agencies" with no numbers, logos or testimonials.
- **No FAQ, no privacy explanation** (where cloud data is stored, who can see invoices), **no payment-collection info** (competitors Bloom/Zoho highlight PayPal/Stripe links. If you don't support it, say so in the FAQ).
- **Stale UI text:** the date picker markup is server-rendered as "July 2026" **[Confirmed]** (today is Sept 2026). It's minor, but it's crawlable text that looks stale.
- "Multi-language support": translations are client-side JS on one URL (49 `data-i18n` nodes). Only English is indexable, which is fine, but don't imply localized pages exist.

### Content that should be added
1. **"Schedule Recurring Invoices That Send Themselves"** section (150–250 words): frequencies, auto-email behavior, editing/pausing, where scheduled invoices live (`/scheduled-invoices` after login).
2. **"Free without an account vs. free account"** comparison table: local browser storage + PDF download vs. cloud history, email send, scheduling, customers list.
3. **"What to include on an invoice"** (brief, 120–180 words, linking to the Guides page for depth): business details, invoice number, dates, payment terms, line items, tax, total.
4. **Visible FAQ (6–8 Qs)** built from real product facts, e.g.:
   - Is InvoiceScheduler really free? Are there limits?
   - Do I need an account to create an invoice?
   - How do recurring invoices work? Do they email my client automatically?
   - Where are my invoices stored? What happens if I clear my browser?
   - Can I add my logo, tax, discount and shipping?
   - Which currencies are supported?
   - Can clients pay online from the invoice? (answer truthfully)
   - How do I stop or edit a scheduled invoice?
5. **Real proof** when available: number of invoices created, a screenshot/GIF of the scheduling flow, 1–3 genuine testimonials.
6. **Footer** with About, Contact, Privacy Policy, Terms, Guides, Help (none exist on the homepage **[Confirmed]**).

### Content that should be removed or improved
- Rewrite "Trusted by Freelancers, Small Businesses & Agencies" → "Built for Freelancers, Small Businesses & Agencies" until there's evidence.
- Replace "No Signup Required to Start" H3 copy with an accurate split (create/download free without an account; email + schedule with a free account).
- Cut generic filler: "seamless, convenient, and secure invoicing wherever you go!", "Invoice Smarter", "get paid faster" (unless you show why).
- Remove the date picker's static month from the server HTML (render on open).

**Recommendations (specific):**
1. **Replace Tailwind Play CDN with a compiled, purged stylesheet.** `npx tailwindcss -i input.css -o assets/app.css --minify` (content: `./**/*.php`, `./assets/*.js`) → typically 10–25 KB. Load with `<link rel="stylesheet" href="/assets/app.css?v=1">`. Expected: largest FCP/LCP/TBT improvement.
2. **Lazy-load html2pdf on click:**
```js
async function loadHtml2pdf(){ if(window.html2pdf) return;
  await new Promise((ok,err)=>{const s=document.createElement('script');
    s.src='https://cdnjs.cloudflare.com/ajax/libs/html2pdf.js/0.10.1/html2pdf.bundle.min.js';
    s.onload=ok; s.onerror=err; document.head.appendChild(s);});}
downloadBtn.addEventListener('click', async ()=>{ await loadHtml2pdf(); /* existing export */ });
```
3. Remove `<script src="/script.js">` (or fix the path).
4. Move the ~140 KB inline JS to an external, `defer`red, versioned file (`/assets/app.js?v=…`) so it can be browser-cached across visits and doesn't delay HTML parsing.
5. Don't start a PHP session for anonymous homepage visitors (call `session_start()` only when a session cookie exists or on auth actions). Then send `Cache-Control: public, max-age=300, s-maxage=3600` so hCDN can cache the homepage.
6. Static assets: `Cache-Control: public, max-age=31536000, immutable` with versioned filenames.
7. After the changes, run PSI mobile and watch CrUX in GSC.
